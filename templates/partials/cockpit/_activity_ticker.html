HOST ROUTING ------------ * Manager / operator host (`request.public_host_kind == "manager"`): reads `cockpit.activity_ticker.cards` (platform-wide events — schools provisioned, MRR delta, webhook drift, support tickets, migration sync). * Tenant host (anything else with an authenticated user on the portal): reads `cockpit.tenant_activity_ticker.cards` (tenant-scoped events — enrollments, fee payments, attendance milestones, parent messages, maintenance windows). NEVER pulls from `cockpit.activity_ticker.*` so operator-platform data can never leak onto a tenant subdomain. * Anonymous / auth shells (login, signup, anything without a user): silent. `request.user.is_authenticated` is required for ANY ticker to render. Bloomberg-style auto-scrolling horizontal feed. Track is duplicated below so the keyframe (`transform: translateX(-50%)`) produces a seamless loop. Pauses on hover / focus-within. Honors prefers-reduced-motion. CONFIGURABLE ------------ `cockpit.activity_ticker.*` (manager-host operator-published payload) and `cockpit.tenant_activity_ticker.*` (tenant-host operator-published payload) share the same schema: .enabled bool — gate the section (default: True for manager when cards present; False for tenant — operator must opt in via SiteSettings) .scroll_seconds int — animation duration; lower = faster (default 40 since v3.60.0) .live_badge_label str — pill label (default: "LIVE") .cards list — ordered list of cards. Each card shape: { text: str — main headline timestamp: str — relative time ("12s ago", "1m ago") icon: str — single glyph displayed left of text (optional) severity: str — success | warn | danger | info (drives icon color) } v3.57.11 backwards-compat: when neither key is populated but the legacy `cockpit.activity_feed.events` shape is present (older configs), we render that instead — but ONLY on manager host so tenant pages don't accidentally surface operator data.
