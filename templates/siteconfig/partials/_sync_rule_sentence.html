{% load i18n %} {% comment %} One schedule rule, read as a sentence instead of printed as a form. This is a WIDGET change and nothing more. The field names still match the model's, because Django maps a model ValidationError dict onto form fields by name and raises ValueError for a key the form has no field for — the constraint documented at the top of forms_sync_schedule.py. SyncSchedule.clean() remains the single validation implementation, so this can never accept something the engine would refuse. WHAT IT FIXES. {{ form.as_p }} printed eight stacked controls with no grouping and no preview, including a "Times" text box that is meaningful for only one of the two "Type" values — with nothing on screen saying which. Read as a sentence, the shape of the rule is the shape of the words, and the irrelevant clause is hidden by JS (and merely labelled, not hidden, without it). WHY EVERY PAIR IS WRAPPED. The line is a flex row that wraps, and the first version let it wrap ANYWHERE — so at the width this editor actually renders at, "between" ended one line and its time box started the next, and the seven day chips broke 6 + 1. A label separated from its control is not a cosmetic problem: it is a label that no longer looks like it belongs to anything. Each label+control pair is now one flex item, so the line can only break BETWEEN pairs, and the day picker is a seven-column grid that fits seven at any width rather than a row that wraps. NO JAVASCRIPT REQUIRED. The days are real checkboxes styled as chips through :checked + label, not buttons that need a script to hold state. With JS off every control works and the form submits exactly as before. {% endcomment %}
