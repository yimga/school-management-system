{% translate "Managed devices: push it once, for everyone" %}

{% blocktranslate trimmed %} If the school manages its devices, none of step 3 applies. Every console can install a certificate authority on every enrolled device at once, and on Apple hardware that is also the only route that skips the Trust Settings screen — a pushed profile is trusted on arrival, a hand-installed one is not. {% endblocktranslate %}

{% translate "Everywhere else, upload the .crt from step 2" %}

{% translate "Google Admin (ChromeOS and Chrome)" %} — {% blocktranslate trimmed %} Devices, Networks, Certificates. Upload it and tick the box that makes it an HTTPS certificate authority; without that tick it is stored and ignored. {% endblocktranslate %}

{% translate "Microsoft Intune (Windows)" %} — {% blocktranslate trimmed %} Devices, Configuration, a Trusted certificate profile. Set the destination store to Computer certificate store - Root, not the user store. {% endblocktranslate %}

{% translate "Windows domain without Intune" %} — {% blocktranslate trimmed %} Group Policy, Computer Configuration, Policies, Windows Settings, Security Settings, Public Key Policies, Trusted Root Certification Authorities. {% endblocktranslate %}

{% translate "Android Enterprise" %} — {% blocktranslate trimmed %} the certificate goes into the device policy as base64, under caCerts. On the box console, manage.py edge_tls --export-mdm writes that snippet out along with every file named on this page. This is not a convenience on Android: a user-installed authority is ignored by apps, so for anything managed it is the only route that works. {% endblocktranslate %}
