# companion-extension icons

This directory holds the three PNG icon sizes Manifest V3 requires:

- `icon-16.png` — toolbar / favicon ribbon
- `icon-48.png` — extension management page
- `icon-128.png` — Chrome Web Store listing + install dialog

## v3.40.0 — RMC monogram icons (programmatic)

The icons checked in here are generated by
[`scripts/generate_companion_extension_icons.py`](../../scripts/generate_companion_extension_icons.py).
The script renders a rounded-square RMC-indigo (`#3A45FF`) badge with
a near-white (`#F4F6FF`) monogram glyph composed from a hand-rolled
5x7 bitmap font table. No external image libraries are used — the
script is stdlib-only (`zlib` + `struct`).

Sizes:

- `icon-16.png` — single "R" glyph centered (three letters do not fit
  legibly at 16x16).
- `icon-48.png` — "RMC" monogram at scale=2.
- `icon-128.png` — "RMC" monogram at scale=5.

The generator is idempotent: running it twice produces byte-identical
output, which is asserted in
[`scripts/test_generate_companion_extension_icons.py`](../../scripts/test_generate_companion_extension_icons.py).

### Regenerating

```bash
python scripts/generate_companion_extension_icons.py
```

To use a different monogram (e.g. when whitelabeling for a partner):

```bash
python scripts/generate_companion_extension_icons.py --monogram FOO
```

## v3.39.0 history

v3.39.0 shipped solid-color placeholders via the same stdlib PNG
encoder. v3.40.0 keeps the encoder shape but composes a recognizable
glyph from a 5x7 bitmap font rather than emitting a flat color block.

## Replacing with photographic / vector brand assets

If the design team produces vector-quality brand assets later:

1. Drop three PNGs into this directory under the exact filenames
   `icon-16.png`, `icon-48.png`, `icon-128.png`.
2. Use the official RMC logo on a transparent or indigo-tinted
   background. Keep the safe-area / cap-height ratio consistent across
   sizes — Chrome scales the 128 down, not up.
3. Run `pngcrush` / `oxipng` to minimize byte size before committing.
4. Delete `scripts/generate_companion_extension_icons.py` (or keep it
   as a regeneration tool if the design team prefers programmatic
   sources) and update this README accordingly.

The existing test `apps/migration_cloud/tests/test_canonical_headers_consistency_v3_39.py`
only asserts PNG-magic-byte prefix + non-empty file, so swapping in
hand-authored assets does not break CI.
