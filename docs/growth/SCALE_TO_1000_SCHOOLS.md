# Scale to 1,000 schools (operating model)

**Reality check:** This is a **governance and cadence** document. It does not create demand. Metrics are for **your** tracking—not claims about the product.

## Phase 0–10: Founder-led

- **Motion:** You + one backup own sales calls, deploy path, and first-week support.  
- **System:** `docs/sales/ENTERPRISE_SALES_SCRIPT.md` + `FIRST_CUSTOMER_ONBOARDING.md` + smoke tests.  
- **Metric to track:** Pilots started / pilots converted (your definition) / **support hours per new school** (keep this from compounding).

## Phase 10–100: Repeatable + referrals

- **Motion:** Templated discovery call, 45-min demo, written pilot. Ask every happy head for **one** intro; track in `docs/growth/CUSTOMER_PIPELINE_TEMPLATE.md` (sheet or internal `/sales/` pipeline on the manager host).  
- **System:** Onboarding % via `/siteconfig/onboarding/`, internal CRM (`/sales/` for control-plane users).  
- **Metric:** Referrals per 10 live schools; time-to-first-success (see onboarding checklist).

## Phase 100–500: Partnerships + inside sales

- **Motion:** 1–2 group partner channels (diocese, group, or regional association) with **one** contact owner each; avoid 20 shallow partnerships.  
- **Hiring trigger:** When founder calendar > 50% on repetitive demos, add **one** person: either sales *or* onboarding specialist—not both on day one. See `docs/company/HIRING_PLAN.md`.

## Phase 500–1,000: Automation and support ops

- **Motion:** Onboarding is **templated and metered**; “white glove” only for top ARR.  
- **System:** Product remains CP-first; scale is **process + staffing**, not new magic features.  
- **Metric:** Churn or dormancy: schools with <20% activation after 30 days get a **single** rescue play, then re-scope.

## Cadence (weekly)

- Monday: pipeline review (internal, honest stages).  
- Wednesday: one technical block for deploy/support debt.  
- Friday: 30 min metrics (activation %, NPS/feedback if you collect it, no vanity dashboards required).
