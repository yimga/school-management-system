# Tenant shell parity — the audit that has to happen

*Written 2026-08-21, from screenshots of the self-hosted box rendering pages that
do not look like the product.*

## What was observed

Two pages on the self-hosted appliance, both logged in as a tenant admin of
Gilead Technical High School:

- **`/authentication/profile/`** — renders under the `RUNMYCAMPUS` platform
  wordmark with an `ADMIN` chip, a **completely empty sidebar** (a "Filter…" box
  and a "Navigation" header with nothing under them), and platform-operator
  chrome ("Search tenants, incidents, commands").
- **`/…/studio/`** — same platform wordmark with a `STUDIO` chip, a sidebar
  containing only "Studio" and "LEAVE STUDIO", and an operator-flavoured
  "Preview tenant" dropdown listing the tenant to itself.

The tenant's own brand is absent. The navigation is empty or near-empty. The
page is framed as though an operator were inspecting a tenant, when the person
looking at it IS the tenant.

**The requirement is simple to state:** a self-hosted tenant must be
indistinguishable from that same tenant on the cloud, except for the hostname.
Same brand, same navigation, same shell, same chrome. No exceptions.

## Why this is not a styling task

Three mechanisms in this codebase can each produce exactly these symptoms, and
they fail in ways that look identical from a screenshot:

1. **Host-split urlconfs.** `UrlConfSwitcherMiddleware` serves `config.urls`,
   `config.tenant_urls`, `config.manager_urls` or `config.public_urls` depending
   on the host. `public_host_kind()` returns `"local"` for any bare IP — and the
   appliance is reached at `10.10.20.137:10000`. A shell that branches on
   `public_host_kind` will take a different path there than on
   `gilead-tech.runmycampus.com`, and an empty sidebar is what that looks like.
   This is the same root as the `/portal/kb/docs-hub/` 404 and the six dead
   Action Hub chips: **dev/local gets a URL surface a real tenant does not.**

2. **The brand cascade.** `RuntimeDefaults` → `School.settings` → wizard overlay
   → `SiteSettings.brand_payload` → context processor → `rmc_theme_meta.html` →
   CSS custom property. Any link unresolved on the appliance and the shell falls
   back to platform defaults — the RunMyCampus wordmark instead of the school's.

3. **Navigation registries.** A sidebar built from a registry filtered by
   role/permission/feature-flag renders empty when the registry is empty, when
   the flags resolve false, or when the permission lookup fails closed. Empty is
   not the same bug as wrong, and the two need separating before either is fixed.

A fourth possibility must be ruled out rather than assumed: the appliance may be
running **older code**, in which case some of this is already fixed and the real
finding is that `/-/version/` reports `unknown` so nobody can tell.

## The method — non-negotiable

Follow `docs/RMC_STANDARD_EXECUTION_LOOP.md`: AUDIT → IDENTIFY → FIX → TEST →
RE-AUDIT → IMPROVE → REPORT. And follow
`docs/ENGINEERING_STANDARD_PROVE_THE_OUTCOME.md`:

> **Audit by RUNNING the thing, not by reading it.** Fetch the page on the
> appliance host AND on the cloud host as the same role, and DIFF them. Reading
> a template tells you intent; rendering it tells you what a school sees.

**No mechanism claim without a state read.** A theory that explains the
screenshot is not a diagnosis. Earlier in this same programme a plausible,
arithmetically sound explanation was written up before a single row was queried,
and it was wrong.

## Scope — every shell, every role, no exceptions

Five shells: `portal_base.html`, `base.html`, `control_plane_skeleton.html`,
`admin/base_site.html`, `marketing/base_marketing.html`.

Five personas: tenant admin, teacher, parent, student, operator.

Two hosts: the appliance (bare IP) and the cloud subdomain.

The cross-product is the audit surface. Sample it honestly — and if you narrow
it, **say what you dropped and why**, per CLAUDE.md's scope-violation rule.

## Deliverables

1. **A parity matrix**: page × persona × host → renders identically / differs /
   errors. Generated by fetching, not by inspection.
2. **A root-cause split.** Every difference attributed to one of: host-split
   urlconf, brand cascade, navigation registry, stale deployment. These have
   different fixes and lumping them together guarantees a wrong one.
3. **Fixes, smallest blast radius first**, each with a test that fails before it.
4. **A permanent seal.** A one-time fix here will regress; the same class already
   has. Prefer a CI gate — a scanner in the style of
   `verify_cross_host_template_reverse.py`, which already proves a template's
   `{% url %}` targets resolve on every host it renders on. The natural sibling
   asserts that a tenant-facing shell renders its brand and its navigation on
   every host it serves.

## Hard rules

- [ ] **A tenant must never see operator chrome.** "Search tenants, incidents,
      commands" and "Preview tenant" are control-plane affordances. Their
      presence on a tenant surface is a finding on its own, independent of
      styling. Note that `scan_tenant_template_operator_links.py` (baseline 0)
      already enforces the *link* form of this rule — extend it rather than
      inventing a parallel gate.
- [ ] **An empty navigation is an ERROR, not an empty state.** A sidebar that
      renders zero items must log loudly and say so on screen. Silence here is
      what let this ship.
- [ ] **The tenant's brand outranks the platform's** on every tenant surface.
      Falling back to the RunMyCampus wordmark is a failure, not a default.
- [ ] **No fix may be verified only on `localhost` or a bare IP.** That is the
      environment that hid this. Verify against a host that resolves to
      `config.tenant_urls`.
- [ ] **Report what you could not verify.** The shared test database is broken
      and CI has run nothing since 2026-08-15; a claim of "tested" that rests on
      neither is a claim about a machine, not the product.
