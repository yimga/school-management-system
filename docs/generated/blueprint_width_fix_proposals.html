RunMyCampus · layout remediation

Width-utilization fix — browser proposals

The control-plane / tenant shells render content in a full-width canvas (grid-template-columns: <sidebar> 1fr; no content max-width). Pages whose content is a sparse single column (lists, short forms, settings toggles) cluster to the left and leave a large empty right gutter on wide screens — the symptom reported on /super/marketplace/blueprints/. There are two honest cures: FILL the width with useful content, or CENTER the measure so the gutter is symmetric breathing room rather than a left-clustered bug. Below: the same Blueprint page rendered current vs. three proposals.

Proposal A

Responsive card grid fill

Each pack becomes a self-contained card; grid-template-columns: repeat(auto-fill, minmax(330px, 1fr)) flows 2–4 cards per row to fill any width and reflows down to 1 column on mobile. Best for catalogs / lists (blueprint, package_rollout, app_catalog, governance queues).

Proposal B

Master–detail two-pane fill

A pack list on the left; the right pane (previously dead space) shows the selected pack's full detail, policy-key preview, and the Apply / Preview / Rollback controls inline. Best for operator workflows where the gutter should hold useful content (blueprint, governance_console, monetization_inspector, sandbox_inspector).

Proposal C

Centered measure center

Keep the single column but margin-inline:auto at a readable max-width (~1080px) so the gutter becomes symmetric breathing room, not a left-clustered bug. The honest fix for pages where full-width inputs would be unreadable: the 9 *_settings.html toggle pages, profile/delegation forms, single forms. Not for catalogs.
