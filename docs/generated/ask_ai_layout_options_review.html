Ask with AI placement options

The current issue is not the AI feature itself. The problem is placement: an always-open full-width helper is being appended near the bottom of the shell. These options keep the assistant useful without blocking the tenant workspace.

Approval options only

Recommended direction

Option A: integrate Ask with AI into the existing copilot sidebar. The app already has a right-side copilot rail, so the fix should reuse that surface instead of adding another AI panel. Ask with AI becomes a Help/KB mode inside the rail, while the old bottom inline helper is retired.

Why not a popup dialog

  • Dialog boxes interrupt the task and cover the form/table the user is asking about.
  • The assistant is a companion tool, not a blocking confirmation step.
  • The existing copilot rail already owns the AI/help space.
  • One rail prevents duplicate AI buttons, duplicate text areas, and competing z-index layers.
