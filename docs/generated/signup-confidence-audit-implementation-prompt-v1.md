# Signup wizard and explainable-confidence implementation prompt

Audit the complete public signup journey before editing. Trace `/signup/` from URL, view/context builders, validation, persistence, country/education registries, recommendation rules, client scripts, verification email, password/MFA, provisioning, analytics, offline behavior, accessibility, localization and error recovery. Inventory every field and contract so no existing capability is lost.

Implement the approved HTML as progressive enhancement: server-rendered and fully usable without JavaScript; five focused stages with resumable local drafts; questions adjacent to answers; balanced desktop columns; one-column mobile flow; one primary action per stage; keyboard/focus/error-summary support; no hidden or clipped content; country-pack and recommendation behavior available without an AI or network dependency. Preserve CSRF, rate limits, tenant isolation, slug checks, verification, MFA and idempotent provisioning.

Replace the current heuristic “confidence” presentation with an evidence-based recommendation envelope. Separate: input completeness, registry coverage, rule/model certainty, calibration quality and contradiction penalties. Never display ≥90% unless every critical evidence group is answered, the relevant country/profile cohort meets a predeclared sample-size floor, held-out calibration meets its threshold, no unresolved contradictions exist, and the chosen recommendation is stable under sensitivity testing. Otherwise show “provisional” or “needs confirmation,” identify the missing answers, and provide the shortest path to improve confidence. Always show the top recommendation, alternatives, reasons, evidence used, evidence not used, registry/version provenance and a user override. Log recommendation version and explanation without storing unnecessary PII.

Use offline deterministic rules and signed/versioned country registries as the baseline. AI may improve explanations or detect inconsistencies, but must not be required to create a school or silently choose compliance settings. When online, evaluate candidate models with stratified holdouts by country, institution type, scale and connectivity; measure Brier score/log loss, expected calibration error, top-choice accuracy, abstention coverage and override rate. Calibrate probabilities (isotonic/Platt/temperature as appropriate), publish thresholds, monitor drift and fall back to rules when calibration or registry freshness fails.

Testing is non-negotiable: unit-test every recommendation rule and confidence component; property-test ranges, missing values and contradictory inputs; contract-test client/server parity; integration-test every wizard transition, save/resume, back navigation, validation, double submit, verification and provisioning; test offline/no-JS/slow-network; test localization/RTL; run accessibility and responsive visual tests at supported breakpoints. Confirm a user can finish with keyboard only and that no required answer is hidden.

After implementation, run a second independent audit against the original inventory and approved HTML. Produce a field/contract parity matrix, confidence-gate evidence, route/click map, responsive screenshots and test results. Fix every scoped gap and rerun until green. Only then update the service-worker cache version if approved UI assets changed, run repository release gates, commit an intentional diff and push the approved commit to `main`.
