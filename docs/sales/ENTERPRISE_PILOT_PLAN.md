# Enterprise pilot plan

## Shape

- **1–2 campuses (or one campus with two “streams” e.g. primary/secondary)** so scope stays measurable.
- **Duration:** 60–90 days default; exit criteria below must be in writing.

## Setup (real product steps)

- Tenant and DNS live; smoke subset from `LAUNCH_SMOKE_TEST.md` on **their** host.
- At least one **academic year**, **departments**, small **user** set, and **classes**; optional: `/siteconfig/onboarding/` for a honest activation %.
- One **report** path proven (view + generate or schedule—aligned to what is entitled).

## Success criteria (choose 4–5)

1. **Login and role-appropriate home** for admin + one teacher.
2. **CCC** opened and at least one domain or routing decision recorded (evidence, not a screenshot fake).
3. **Student 360** or equivalent profile path for **at least one** real student id (or admit “not in scope” explicitly).
4. **One** scheduled or on-demand report demonstrably ran in their environment (with workers if email).
5. **Support channel** with SLA you can keep (e.g. business-hours email).

## Rollout path

- **Phase A:** Stabilize year/term and people.  
- **Phase B:** Reports and comms.  
- **Phase C:** Optional marketplace packs / Studio — only if entitlements and training allow.

## Stakeholder checklist

- [ ] Business owner: pilot scope and date.  
- [ ] IT: DNS, TLS, email egress for reports.  
- [ ] Academics: year/term calendar owner.  
- [ ] DPO (if required): who accesses student data in the pilot.

## Handoff to production

- Retention of pilot data or **fresh** go-live per `FIRST_CUSTOMER_ONBOARDING.md` demo-to-live section.
