# Tenant RAG bundles

RunMyCampus keeps one canonical embedding source of truth:
`siteconfig.AIEmbeddingStore`. A tenant RAG bundle is a signed transport
format for moving that tenant's canonical rows between cloud and local-hub
deployments. It is not a second vector database.

## Security and lifecycle contract

- Bundles are bound to one school UUID and signed with HMAC-SHA256.
- Production export/import requires `TENANT_RAG_BUNDLE_SIGNING_KEY`.
- Every record preserves its document ID, chunk SHA-256, embedding model,
  vector dimensions, scope, retention deadline, source timestamp, metadata,
  and active/tombstone state.
- Import is atomic and idempotent by tenant, scope, document ID, and chunk
  hash. A newer tombstone blocks replay of older active chunks.
- Retrieval excludes tombstones, expired records, other tenants, and vectors
  generated by a different embedding model.
- Tenant bundles never include platform-global (`school_id IS NULL`) rows.

## Operator workflow

Use the same embedding model on the source and destination deployments.

```bash
export TENANT_RAG_BUNDLE_SIGNING_KEY="<shared-secret>"
python manage.py export_tenant_rag_bundle \
  --school <school-uuid> \
  --scope policy \
  --output var/bundles/<school-uuid>-rag.json

python manage.py import_tenant_rag_bundle \
  --school <school-uuid> \
  --input var/bundles/<school-uuid>-rag.json
```

When the destination uses PostgreSQL pgvector, run the existing idempotent
backfill after import:

```bash
python manage.py migrate_embeddings_to_pgvector
python manage.py verify_pgvector_index --strict
```

JSON cosine retrieval remains the small/offline fallback. Pgvector remains
the production-scale path. SQLite-vector extensions are not a source of
truth and are not enabled without a measured, separately approved need.

## Gate

```bash
npm run verify:tenant-rag
```
