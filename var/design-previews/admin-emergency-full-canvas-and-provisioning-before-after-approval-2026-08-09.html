Why approved HTML did not become the rendered product

The problem is ownership and proof coverage, not lack of approved design direction.

5 critical
ADMIN-OWNERSHIP-001

Four generations own the same geometry

Workspace 10×, canvas-contract, inline critical CSS and approval-v15 all target the shell/form. Source order and specificity decide the winner page by page.

ADMIN-COVERAGE-002

“Platform-wide” meant 11 templates

The legacy scanner sees 11 direct base-site pages and 44 filename-matched CSS files. The actual registries contain 197 operator and 274 tenant models.

ADMIN-BROWSER-003

Outer boxes pass while fields fail

Existing browser proof measures workspace tracks and overflow. It does not measure input occupancy, contrast, stacked sections, repeated navigation or excessive page length.

THEME-CONTRAST-004

Dark shell, light utility card

The shell can be dark without Tailwind’s .dark selector controlling a copied bg-base-50 card. That produces the white visibility blocker.

FORM-DENSITY-005

One form strategy cannot fit 471 models

Intrinsic native widget widths and always-stacked sections create narrow left columns, vast dead space and forms many screens long.

PROVISIONING-006

Recommendations stop before plan binding

The deterministic setup manifest exists, but high-impact operating inputs, versioned blueprint resolution and an explainable subscription recommendation are incomplete.
