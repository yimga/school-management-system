AGGRESSIVE AUDIT v14b — surfaces must NOT look the same

Page intelligence = different layouts, not one shell with new labels

Prior waves kept a cookie-cutter workbench (band + metrics + rail + tools) on every Django admin URL, then swapped copy. That is the opposite of page awareness. This board goes harder: each surface type earns a different geometry, chrome set, and information density — operator vs tenant also diverge where jobs diverge.

Hard rule: If you blur the page and cannot tell index from list from form from delete, the design failed. Shared tokens and quality — not shared chrome stacks.
1 · Job firstIndex = find. List = scan/filter. Form = edit. History = timeline. Delete = decide. App index = dossier. Different jobs → different UI.
2 · Chrome must earn pixelsIf a control is inert on this surface, it is banned — not greyed, not “for consistency.” Gone.
3 · Host identityOperator = fleet backoffice. Tenant = school config engine. Same premium bar; different CTAs, rails, and catalogs.
4 · Density ≠ sameness2-up forms, table theater, and catalog search grids are three different density systems. Do not force one grid on all.

2 · Six surface archetypes deliberately different geometries
A · Index = Discovery

Search-first catalog

No tools column. No CRUD +. Catalog is the product. Operator and tenant catalogs share search grammar but different primary CTAs and section sets.

  • Geometry: 1 main column (+ optional sticky shortcuts)
  • Fold 1 = search + first catalog row
  • Details collapsed / numbered
B · Changelist = Table theater

Rows own the canvas

Almost all MAIN pixels are the table. One band with title + Add + Filters. Tools = + / ⚡ / ⌘K / ↑ only. Rail = live filter state — never manifesto.

  • Geometry: 3-col list workbench
  • Bulk actions appear only when rows selected
  • No second Filters button in toolbar
C · Form = Dense editor

Fields pack; sections collapse

2-up scalars. Numbered <details> for M2M and fieldsets 3+. Sticky Save ▾. No Filters tool. No Form/Audit tab chrome. Rail = this record.

  • Geometry: 3-col form workbench
  • Long models shrink vertically via disclosure
  • Audit / History via Save ▾ or rail links
D · History = Timeline

Not a fake form

Kill workbench tools. Two columns: timeline MAIN + object identity rail. Jump back to change form is the only primary CTA.

  • Geometry: 2-col
  • No metrics strip
  • No + / Filters / View site tools
E · Delete = Decision

One card. Two outcomes.

Centered decision surface. Related objects as a compact numbered list. Confirm / Cancel only. No rail, no tools column, no catalog chrome.

  • Geometry: 1-col max-width ~40rem
  • Destructive hierarchy clear
  • Zero fluff copy
F · App index = Dossier

One app, not mini-home

Not a second operator index. App name + model table for that app only + jump to Config if relevant. Tenant dossier never shows fleet CTAs.

  • Geometry: 2-col
  • Models list fills MAIN
  • No duplicate hero manifesto
