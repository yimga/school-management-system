Implementation prompt

Tenant-wide audit/fix loop

This is the prompt shape to apply after approval. It is intentionally tenant-scoped and excludes operator UI redesign except for hard separation/security checks.

Audit tenant-wide first, then implement. Do not assume coverage.

Scope:
- Tenant surfaces only: signup, email verification, login/MFA, Setup Studio, blueprints, import/migration, Theme & Experience, Money Center, dashboard, messages, academics, reports, workflow center, feature controls, launch readiness, and daily school operations.
- Operator surfaces are out of scope except tenant/operator separation checks.

Design contract:
- Apply Option A warm command workspace to tenant operational pages that currently render as sparse text or cramped panels.
- Use full available width intelligently.
- Use bounded vertical scrolling inside long work zones; avoid pages that run endlessly.
- Live preview must work 100% of the time through inline preview, sidecar, modal, popout, or new tab fallback.
- Palette previews must show header, sidebar active state, hero, buttons, status, tables, charts, alerts, forms, and role dashboards.

Tenant lifecycle audit:
- Trace signup -> verify email -> login/MFA -> setup -> blueprint -> import -> brand -> readiness -> daily operation.
- Every step must have one primary next action, a clear blocker state, and a tenant-scoped destination.
- No tenant path may redirect to /super/ or operator /admin/.

Blueprint audit:
- List all tenant-safe blueprints.
- Preview each with a tenant school and assert no pack_not_found conflicts.
- Tenant page must show row-level Preview and Apply/Request approval states.
- Platform-only blueprint controls must remain hidden.

Validation:
- Run focused Django tests for tenant blueprints, tenant onboarding links, tenant lifecycle, theme experience, and operational workbench surfaces.
- Run Django check and template/static lint where available.
- Re-audit generated route/template inventory and close gaps before commit.
