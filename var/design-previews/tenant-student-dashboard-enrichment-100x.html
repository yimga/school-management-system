Closing the last gap: the student dashboard is data-thin

Parent, teacher and admin role-homes are data-rich. The student role-home is honest but hollow — its view (student_learning_home) only fetches the homeroom name and the unread-message count, so the premium grammar renders two tiles and a static "next actions" list. To be best-in-class for the student, the view must surface the data the student is already entitled to see: today's timetable, their own attendance, upcoming work, and (when published) results.

Same .rmc-dh grammar already shipped — no new component CSS. The change is a data-aware view + a richer include. Nothing below renders fabricated data; every panel is conditional and degrades to an empty state when its data isn't present.

What's safe to show — and the one decision for you

  • SAFE — own record Timetable, attendance, upcoming assignments, announcements, messages. These are the student's own data; surfacing them on their dashboard exposes nothing new — the data already lives behind links they can open. Pure win, no governance question.
  • YOUR CALL Results / grades. Schools differ on when a student may see marks. Proposed safe default: only show results once the term/assessment is published (the platform already tracks a published-terms flag, and parents are gated by can_view_results). Three options below.
  • HONEST Every panel stays conditional — if a school hasn't entered timetable/marks, that panel shows an empty state, never fabricated numbers. Matches the student role-home's existing "honest" contract.
