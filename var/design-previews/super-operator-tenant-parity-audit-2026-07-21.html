Surfaces already look clean. The remaining failure mode is vertical chrome stacking + cookie-cutter sameness: every hub opens with the same explain → frame → static “Operational” → readiness → AI cards recipe, before the work. Tenant school admins do not get manager /super/; they get a fragmented twin (Backend + School Configuration + Studio + Configure). This audit makes both planes even — purpose-curated pages, live information tags, full-width intelligence, and breathing room without fluff.

Tenant “their /super/” = school admin hubs on portal_base/backend_base (/authentication/backend/, /school/configuration/, /school/studio/, /portal/configure/, Feature Control). 01 · Verdict what must change

What’s already strong

  • Full-width canvas policy on CP (rmc-cp-v8-full-width.css) — horizontal max-width traps are largely fixed.
  • Landing personality exists: globe deck / Migration Cloud command center are purpose-curated.
  • Zero-click strip only renders with real triage data — good de-fluff precedent.
  • Tenant backend marks intelligent-full-width; design system + tokens are in place.

What’s still broken (the real pain)

  • Cramping is vertical, not horizontal — 4–7 chrome bands before first useful control.
  • ~40+ pages stamp static Operational badges (zero signal).
  • Tenant config cards hardcode status: "ready" for every section — theater density.
  • Billing collapses real KPIs behind <details> while stacking two page headers + AI cards.
  • Operator vs tenant use the same Option-A workbench grammar, so hubs feel identical regardless of job.

07 · Five page archetypes pages must not all look the same
MissionLanding / command
Operator Home, Migration command center, Tenant Backend dashboard. Personality allowed (globe, pillars, pulse). Minimal explain. Live chip-row mandatory. Keep curated — do not force workbench chrome onto landings.
Fleet listTables / search
Schools, tickets, incidents, webhooks, users. Title + chips + sticky filters + full-width .rmc-data-table. No Option-A strip. No dual headers.
Money deskBilling / finance
KPIs always visible. Status chips for PSP / past-due / sync. Ledger table primary. AI only in rail. Never collapse money behind details.
Setup mapConfig / branding / features
Progress + blockers first. Section rows with live state tags. One CTA per blocker. Definitions in rmc_info_tag ⓘ — not body paragraphs. Tenant + operator config share this grammar.
MonitorSLO / health / audit
Stateful pills (Migration-style) + spark/time context + drill-in. Ban static Operational. Prefer “All clear” / “Degraded” / “Breach” from live data.
08 · Consistency contract stop repeating yourself

Hard rules (both hosts)

  1. One title system — shell H1 or center frame, never both; never also studio page_header.
  2. Live tags or no tags — delete static Operational / ready wallpaper.
  3. Work above fold — first interactive control or primary number within ~320px of canvas top.
  4. Full width for work — tables/KPIs edge-to-edge of canvas; prose/forms may narrow intentionally.
  5. Info tags for definitions — move “what is this” out of strips into ⓘ.
  6. Breathing via fewer bands — increase section gap only after chrome count ≤ 2 above content.
  7. Archetype attribute — data-page-archetype must be one of the five; CSS contracts per archetype.

Evenness map (operator ↔ tenant)

  • Operator Home ↔ Tenant Admin Home (Backend, simplified)
  • Operator Schools/Fleet ↔ Tenant People/Classes lists
  • Operator Billing desk ↔ Tenant Finance desk (same money archetype)
  • Operator Configuration engine ↔ Tenant Configuration (setup map)
  • Operator Migration monitor ↔ Tenant Migration connector (monitor, scoped)

Same archetype grammar, different data scope. Not the same template copy-paste with “Tenant scoped only” text.
