Aggressive Django and Studio surface rework

This is the proposed body-level contract before production implementation. It addresses the screenshots directly: no narrow centered forms, no squeezed live preview, no sticky bars covering fields, no wasted Studio void, and no iframe-only Automation failure path.

What changed in this proposal

Live preview is promoted to a controlled system: inline when small, drawer when wide, popout when comparing, and new tab when embedding is blocked.

Django forms use a full-width field matrix with a compact action rail. Automation gets a native recovery cockpit instead of showing a dead frame.

Current problem pattern

Experience and Theme mode

  • Large blank area appears above actual work, then the useful editor is pushed below the fold.
  • Live preview and settings are squeezed into narrow columns, causing vertical text and overlap.
  • Right context rail competes with the canvas instead of behaving like a collapsible assistant.
  • Preview is treated as a small widget even when it needs the full screen.

Implementation loop after approval

Audit, fix, re-audit, then commit

This is the exact loop the implementation must follow. It is page-by-page and route-by-route.

No assumptions Proof required
1. Inventory
List every Django admin, tenant backend, operator config, Studio, Workflow, Feature Control, Report Card, Dashboard Preview, Forms, Communications, and Launch route.
2. Classify
Mark each route as tenant, tenant backend, operator, manager, or shared. Wrong-plane links are critical security defects.
3. Scan layout
Find narrow max-width caps, sticky overlays, critical iframes, overflowing text, clipped rails, and duplicated preview controls.
4. Apply contract
Use shared command, grid, main, rail, preview system, save dock, and error recovery zones.
5. Fix Studio modes
Overview, Experience, Automation, Outputs, Launch, and Control must share the workbench contract.
6. Fix Django pages
Change forms and changelists must use full width intelligently and keep actions from covering fields.
7. Live preview proof
Inline, drawer, popout, and new-tab preview modes must exist where user-visible changes are made.
8. Automation proof
Reproduce the 502/500 route, fix root cause, and keep native recovery for future embed failures.
9. Validate
Browser screenshots at 1366, 1536, 1920, and mobile, plus Django checks, focused tests, and gap report.
