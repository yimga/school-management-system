Data Table Lab — Audit → Elevate

Third in the platform-wide series after the sidebar & ⌘K palette. 377 list pages already carry the .rmc-data-table class — so one progressive-enhancement engine attaching to it lights them all up with zero per-page edits. Below is the proposed elevation, fully interactive.

What we found (the "before")

  • Strong base already exists: shared density (localStorage), pagination grammar, bulk-select + sticky action bar (with copilot), row-detail drawer, mobile card-stacking.reuse
  • No click-to-sort. Sort is hardcoded server .order_by() — headers aren't clickable.gap
  • No instant filter. Every filter is a full page reload via GET form.gap
  • No column show/hide. Columns fixed per template.gap
  • Density isn't cascade-configurable. Per-browser only, no per-tenant default.gap
  • No keyboard row nav. tabindex present, no arrow handling.gap

The elevation (the "after")

  • One engine attaches to existing .rmc-data-table → hundreds of pages, no template churn.platform-wide
  • Instant filter of loaded rows + <mark> highlight (CSP-safe).live
  • Click-to-sort columns with aria-sort (numbers/dates/text aware).a11y
  • Column show/hide (⚙) + density toggle, both per-user.personal
  • Keyboard nav ↑/↓ rows, ↵ opens; composes with existing bulk-select.fast
  • Cascade-configurable defaults (platform→school→user). No migration.genius

Mockup only — no backend. The shipping engine (rmc-table-intelligence.js) would progressive-enhance any table.rmc-data-table already on the page (377 templates), compose with the existing bulk-select / row-drawer / pagination, read defaults from the SITE cascade (new table_* prefix owner, zero migration), and persist per-user density + hidden columns to localStorage. Honest scope: filter & sort act on the rows loaded into the page (server pagination unchanged); a later phase can push sort to a ?sort= query param for full-dataset sorting.
